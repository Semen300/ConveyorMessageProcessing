# Асинхронная обработка писем

Решение реализует конвейер обработки email-адресов: для каждого уникального пользователя получает список писем, проверяет письма на спам и формирует отсортированный отчет. Стадии соединены каналами Go и работают одновременно, поэтому результат одной стадии передается дальше сразу, не дожидаясь завершения всей предыдущей стадии.

## Устройство решения

Реализация находится в [`spammer/spammer.go`](./spammer/spammer.go).

### `RunPipeline`

Для `N` функций-обработчиков создаются `N+1` небуферизованных каналов. Каждая функция запускается в отдельной горутине и получает входной и выходной каналы соседних стадий. После завершения обработчика `RunPipeline` закрывает его выходной канал: следующая стадия дочитывает данные и завершает цикл чтения. `WaitGroup` позволяет дождаться завершения всех обработчиков.

Так данные проходят через конвейер потоково, а закрытие каналов обеспечивает корректное завершение цепочки.

### `SelectUsers`

Входные значения интерпретируются как email-адреса. Для каждого адреса параллельно вызывается API получения пользователя. Пользователи могут вернуться не в порядке входа; уникальность определяется по email из результата API, поэтому алиасы одного пользователя не приводят к дубликатам. Доступ к множеству уже обработанных email защищен mutex. Стадия дожидается всех запросов перед завершением.

### `SelectMessages`

Полученные пользователи накапливаются в небольшую очередь и объединяются в батчи размером не больше разрешенного API максимума. Запросы для полных батчей запускаются параллельно; оставшийся неполный батч также обрабатывается в конце. Идентификаторы писем отправляются в выходной канал по мере получения, а перед завершением стадия дожидается всех запросов.

### `CheckSpam`

Для каждого идентификатора письма запускается проверка на спам. Буферизованный канал-семафор ограничивает число одновременно выполняемых проверок допустимым лимитом API. Слот освобождается после завершения запроса, а `WaitGroup` обеспечивает завершение всех проверок до возврата из стадии. Результат передается как `MsgData`.

### `CombineResults`

Стадия собирает результаты проверки, поскольку для сортировки необходимо дождаться всех писем. Затем сортирует их: сначала письма со спамом, затем остальные; внутри каждой группы — по возрастанию идентификатора. Отсортированные результаты преобразуются в строки формата `<has_spam> <msg_id>`.

## Предоставленные API и тесты

[`spammer/common.go`](./spammer/common.go) содержит предоставленные типы, лимиты и API, используемые решением: `GetUser`, `GetMessages` и `HasSpam`. Это внешние по отношению к реализации стадии зависимости; в решении их поведение не реализуется.

[`spammer/main_test.go`](./spammer/main_test.go) содержит тесты конвейера и стадий. Тесты служат для проверки поведения и не являются частью решения.

## Запуск тестов

Из каталога `spammer`:

```bash
go test -v -race
```
